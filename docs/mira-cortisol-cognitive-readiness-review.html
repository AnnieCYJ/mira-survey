必须先讲清的一件事： 你问"趋势图"和"节律推算"是不是一套。它们其实是两套、用途不同——
· 首页睡眠节律卡那条曲线 = proxy（推算）：每个 30 分钟窗口由实测 HRV/EDA/体温/心率直接算，没有 cosinor 拟合（v18.116 已主动废弃 cosinor 补曲线）。
· cosinor（节律）不参与这条趋势线，只在详情页做"持续偏高 / 节律紊乱"状态判定。
所以下面分两块评：proxy 评"趋势图算得对不对"，cosinor 评"节律判定靠不靠谱"。

A. 皮质醇趋势（proxy 推算）—— 结论：结构站得住，但有 3 处要修

设计上做得对的地方（这是优势，DD 时可以直接讲）：
  • 逐时段基线（cortisolProxy.ts:159-164）：皮质醇有强昼夜节律，凌晨本就高。代码把一天切成 48 个 30 分钟槽，每个槽跨天取同一时段的中位数作基线——凌晨比你的凌晨、午后比你的午后。这避免了"凌晨永远被判偏高"。这是最正确的一步。
  • 稳健统计：用中位数 + MAD×1.4826（:116-129）而非标准差，对运动伪迹/漏检离群点稳健，是生理信号处理的标准做法。
  • 近期加权基线（recencyBaseline）：近 2–5 天权重更高，与 Oura/Garmin"rolling average weighted toward recent"一致。
  • 基线不含今天（:188-189）：防止今天的活动把自己的基线抬高、系统性低估偏离。
  • tanh 压缩（:397）：单项极端信号不会把总分打爆。
  • 缺测不编造（:392-393, :20-21）：某窗口无生理信号 → 该槽 null，UI 留空。诚实，符合"不画虚线"的承诺。
  • 方向符号有生理学依据：HRV 反相（HRV↓=交感占优）、EDA/体温/心率正相、活动负相——与交感-副交感模型一致。
要修 / 要知道的 3 处：
  • ① 权重是启发式，没有任何验证回归。 PROXY_WEIGHTS（:58-65）：hrv .26 / eda .24 / temp .18 / rhr .14 / activity .10 / sleepDebt .08。方向对，但"为什么是这些数"没有文献或数据支撑。对比之下 WHOOP/Garmin 的皮质醇/压力模型是专有训练好的 ML，不是简单加权 z 求和。→ 对外可讲"结构同 WHOOP/Garmin 多输入融合"，但必须承认权重未经验证。
  • ② EDA 地板 EDA_FLOOR=20 可能让 EDA 整路失效。（:72, :346）注释写"低于 20μS 视为极静息/未佩戴就不计入"。但手腕 GSR 的典型量程往往远低于 20μS（很多消费级腕部 EDA 在 0.1–5μS 量级）。须用 Veepoo HK18 固件规范核对 EDA 单位与量程——如果实测值普遍 <20，EDA 这一路（权重 .24，几乎最高）就永远不进模型，实际只剩 4 路甚至更少在算，但权重表还写着 6 路。这是最可能悄悄拉低可信度的坑。
  • ③ sleepDebt 权重（.08）全项目从未传入参数，是死权重。（:386-390 只在 opts.sleepDeficit 非空时生效，而全代码没有任何调用方传这个字段）。结果：有效权重被自动重归一，但文档写"合计 1.0"会误导。要么接上睡眠债输入，要么从权重表里删掉、把权重重新归一。
    另外尺度下限（HRV 3ms / EDA 2μS / RHR 2bpm，:335/344/375）虽防止噪声放大，但对你这种佩戴稳定的个体，反而会把 1bpm 的正常波动放大成"激活"——属保守设计，需知晓。
你实际在趋势图上看的是什么（这点必须懂，否则会误读）： 因为 proxy 用的是"逐时段基线"，曲线是去趋势（de-trended）的——它显示的是"相对你自己同时段的基线，今天这一刻激活/承压了多少"，不是生理上"晨高夜低"的绝对皮质醇曲线。所以你不会在图上看到"早上一条峰、半夜一条谷"的经典形状，这是设计使然，不是 bug。
→ 如果你希望用户也能看到"我的昼夜节律长什么样"，正确做法是：把 48 槽基线曲线作为"正常节律"参考线画出来，再把今天的偏离叠上去。而不是拿去趋势的 proxy 值再套 cosinor。

A2. 皮质醇节律（cosinor）—— 数学正确，但概念上要小心

fitCosinor（cortisolRhythm.ts:64-95）是标准的单频 cosinor 最小二乘回归（y = MESOR + β·cos + γ·sin），与开源 CosinorPy 同算法，数学上没问题。它用在详情页的状态判定上：

  • 持续偏高：当日均值 > 个人 14 天基线 P75（:225-231）—— 用日均值判断，这部分合理。
  • 节律紊乱：振幅 < 15% 日均 或 峰值不在 06–11 点（:234-242）—— 阈值偏启发式，但因为作用在代理值上，生理含义更松。
概念坑（不影响趋势线，但影响"峰值在 X 点"这句话的可信度）： cosinor 套在 proxy 值上（:166 对多日 pooling 的 proxy 拟合）。但 proxy 已经用逐时段基线去掉了昼夜分量，再在它上面拟合昼夜峰值，等于对去趋势后的残差二次提取节律——报出来的"峰值时刻"是残差结构，不是真实皮质醇峰值。建议：要么 cosinor 只用于"昼夜形状是否存在/是否紊乱"的判定（不报具体峰值时刻），要么改用原始（非去趋势）信号。好在这条路径不在首页趋势线里，趋势线本身干净。

B. 认知准备度（脑力准备度）—— 结论：当前是"最弱形式"，但有成熟开源方案可重建

当前实现（cognitiveLoad.ts:333-343）： 
computeMorningReadiness(p){
  circAdj = clamp(50 + 50·sin(2π·(wakeH − peakH + 6)/24),0,100)/100  // 默认 0.5
  return 0.7·(p.rec·80 + 20 − p.debt·8) + 0.3·(circAdj·100)
}
其中 rec = 睡眠恢复/100。也就是说：认知准备度 = 睡眠分 ×0.7 + 一条正弦 ×0.3 − 睡眠债惩罚。
  • 它完全没有用夜间 HRV、静息心率、体温这些真正代表"恢复/承压"的自主神经信号。
  • 自带 P0-1 bug（你之前踩过的）：绝对口径下正常睡眠 rec≈0.75→80 分；相对口径下"和平时一样" rec=0.50→60 分。戴满 5 晚那刻起，认知准备度整体凭空掉 14–20 分，而睡眠根本没变。
  • 那条正弦（circAdj）中心在 50、权重 0.3，基本是个弱装饰项。
你的直觉是对的——认知准备度本来就该有成熟方案，而且开源/文献都很扎实：

① 公开文献与方法（可引用）

  • Oura Readiness（公开文档）：9 个贡献因子，每个都对个人基线比较——RHR、HRV Balance（14天 vs 3月）、体温偏移、Recovery Index、Sleep、Sleep Balance、Sleep Regularity、前日活动、活动平衡。复合权重专有，但贡献因子的构成公开（support.ouraring.com）。
  • Kubios HRV Readiness：把当前静息 HRV 对 3 个月个人基线，用 PNS 指数（副交感）。方法公开、被 1800+ 高校使用。
  • WHOOP Recovery：HRV(rMSSD) + RHR + 呼吸率 + 睡眠。
  • HRV4Training（Marco Altini, PhD）：主张 readiness 就是 HRV（RMSSD vs 基线），并明确反对把睡眠+活动+HRV 叠成一个分（会"双重惩罚"——睡差已体现在 HRV 上，再扣一次睡眠分是重复）。这是重要反例，提醒别简单线性叠加。
  • 共同文献基底：HRV Task Force 1996、Plews/Buchheit 的 HRV-readiness、Lamberts 的 RHR drift、Gabbett ACWR、Stanley 等。

② 开源实现（可审计、可借鉴）

  • NOOP（github.com/ayiskakov/noop）：Readiness 综合 HRV vs 基线(Plews/Buchheit) + RHR drift(Lamberts) + 睡眠呼吸率漂移 + 训练负荷平衡(Gabbett) + 单调(Foster) → Primed/Balanced/Strained/Run down，每条都标了引用。是最贴近你想法的透明实现。
  • zepp-health-analytics：Recovery = HRV 0.6 + RHR 0.4（对基线 z-score），引 Garmin HRV Status / AI Endurance / HRV4Training。
  • google-health-mcp：Readiness 启发式 HRV 45% + RHR 30% + 睡眠时长 25%（对基线），并明确标注"简单、可审计的启发式"。
  • 底层工具（提供 HRV 指标，不含复合分）：NeuroKit2、Kubios Lite、HRV-analysis(Parisi)、pyhrv。
建议的重建方向（对齐文献 + 有开源参考，且顺带修掉 P0-1）： 把认知准备度从"睡眠分 rescale"改成 Oura/NOOP 式多贡献因子——
  • 主导信号 = 夜间 HRV（对 14d/3mo 基线）+ 静息心率偏移（app 已经在算，直接复用）。这正是 Altini/Kubios 反复强调的"生理响应主信号"。
  • 睡眠作为其中一个贡献因子（而非全部），权重参考 zepp 的 HRV 主导 + RHR + 睡眠时长结构。
  • 遵循 Altini 的告诫：不要把"睡眠分"和"HRV"线性叠加导致双重惩罚——用 HRV 作为恢复主信号，睡眠只作补充上下文。
  • 这样相对/绝对口径切换不再让分数凭空跳变（因为不再依赖睡眠分 ×80+20 这种刚性线性映射）。
评估范围：皮质醇 proxy 推算 + cosinor 节律判定 + 认知准备度。全天状态趋势（自研曲线）按用户要求另议。所有"开源/文献支撑"结论基于公开文档与论文，本 app 的具体权重/复合公式尚未与金标准（唾液皮质醇、PSG、PSS 量表、认知任务电池）做过对照验证——这是下一步最该补的硬通货。
