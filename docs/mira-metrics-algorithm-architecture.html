2睡眠恢复

取数
只认「今晚这一觉」 findTonightSleep() —— 今天的睡眠摘要，或昨天那条但起床时刻 < 12:00（跨午夜记录常落前一日）。拿不到就是 null，UI 显「—」，不拿更早的存档冒充。
基线
近 14 天四维个人中心 buildSleepDimensionCenters() —— 时长 / 深睡% / 效率 / 起夜次数，各取个人中位。刻意排除今晚，否则今天的表现会把自己基线拉高、偏离被系统性低估。
闸门
基线 ≥ 5 晚才切相对口径 MIN_D = 5。不足 → 走绝对口径（固定目标：时长 7.5–8.5h 满分、深睡 ≥20%、效率 ≥85%、起夜 3 次归零）。⚠ 切口径那一刻分数会跳，这是已知设计而非 bug。
计分
相对口径：每维算「离自己平时多远」 relNorm = clamp(0.5 + (今天/基线 − 1) × 0.5/tol)
容差 tol：时长 10% · 深睡 25% · 效率 6 个百分点 · 起夜（仅当基线 ≥0.8 次才纳入）
权重 W_D .30 / W_DEEP .28 / W_EFF .22 / W_G .20，缺项权重重归一。
⇒ 每项都等于基线 → 正好 50 分。
输出
score · mode · baselineDays · daysToReady · regularity 档位词走 sleepRecoveryTag()：相对 58/42（高于平时 / 与平时持平 / 低于平时）；绝对 80/60。

3脑力准备度

公式主体
0.7×睡眠侧 + 0.3×节律相位
睡眠侧
rec×80 + 20 − 债×8
四档阈值
70 / 40
取数
rec（睡眠恢复 0–1） 直接复用 computeSleepPersonalized().score / 100，与首页 chip 同源（v18.144 起统一）。没有「昨晚这一觉」→ rec = null → brainReserve = null → UI 显「—」（诚实空态）。
睡眠债
7 天指数衰减欠账 debt = Σ max(0, 8h − 当日时长) × exp(−d/5)，d = 1..7。每欠 1 小时扣 8 分准备度。
节律相位
正弦波按起床时刻取相位分 circAdj = clamp(50 + 50·sin(2π(wakeH − peakH + 6)/24), 0, 100) / 100
peakH 来自 14 天皮质醇反推值的 cosinor 拟合峰值时刻（acrophase），取不到默认 8 点。
输出
brainReserve（晨间储备）→ 再经 ODE 消耗得到 brainRemaining 逐时消耗用 computeHourlyLoad()：E(t+dt) = E(t) − fatigueDrive·dt + recoveryDrive·dt，30min 步长，全天 48 点。brainUsed = reserve − remaining。

4心理压力

基线
14 天逐 30min 槽的稳健中心 + 尺度 EDA / HRV / HR / 体温各自建「同时段」基线（皮质醇类节律指标必须同时段比较，否则凌晨会被白天样本判成异常）。中心 = 加权中位（半衰期 7 天，10–90% 截尾），尺度 = MAD×1.4826，退化时用 IQR 兜底。
门控 ①
设备漂移检测 今日 EDA 全天中位 vs 基线中位，稳健 z ≥ 4 → 判定接触不良，只剔除 EDA 三路（权重 0.52），剩下 HRV/HR/体温重归一后继续算。不整段清零。
门控 ②
运动门控（4 层） L1 固件运动段 + L1b 运动后恢复期 + L2 MET/步数 + L3 心率残差 → 判为运动的槽直接排除，不参与压力判定。（运动会让 EDA/HR 同向变化，不排除就会把跑步读成高压。）
融合
6 特征加权稳健 z 每路：生理可信区间校验 → 稳健 z → clamp(±2.5) → × 权重 → 按权重和归一。
权重 皮电水平 .30 / HRV 下降 .22 / 心率上升 .16 / 皮电上升趋势 .14 / 体温偏移 .10 / 皮电波动度 .08。
参与特征 < 2 的槽不给结论。权重是「有文献方向依据的初始值」，不是拟合系数。
映射
z → 百分位（单边） pct = 50 + 50·tanh(z/2)。单边化的理由：压力只有「偏高」这一侧有意义，「远低于基线」不是信号。
全天读数 = 所有参与判定槽（含平静槽）的百分位均值。
闸门 ③
自报校准 把用户自报的压力情绪与同时段生理分配对算相关系数 r。基线 < 3 天 → 断开；r < 0.2（已证明对你无效）→ 不给数字；其余情况照出数字并标注未校准。
输出
0–100 百分位 + 三档标签 切点 50 / 70 → 较低压力 / 中等压力 / 较高压力。另外输出信号完整度（权重和）用于降级提示。

5皮质醇活性

戒指没有皮质醇传感器，这一项是反推的相对量，不叫「皮质醇值」。业界同做法（Garmin 压力分 vs 唾液皮质醇 r = 0.29–0.71；Body Battery vs 晨起皮质醇 r = 0.52）。

信号权重方向生理依据
HRV0.26反相迷走张力↓ → 交感占优 → HPA 轴激活
EDA / 皮电0.24正相汗腺受交感神经直接支配
体温偏移0.18正相下丘脑体温设定点上移 = 交感激活
静息心率偏移0.14正相交感激活 → 心率升高
活动强度0.10负相运动短期压制 HPA，需从总分中扣除
睡眠债0.08正相深睡不足 → 次日晨间 HPA 失调
基线
近 14 天、不含今天、按 30min 槽 每槽各信号取加权中位 + MAD 尺度。用 MAD 而非标准差，是为抗漏检与运动伪迹。基线不足 3 天 → UI 显「建立基线中」。
合成
z 加权合成 → tanh 压缩 raw = Σ(wᵢ·zᵢ) / Σwᵢ → v = 50 + 50·tanh(raw/2)。
映射函数与「心理压力」刻意同一套（一个项目里所有 z→有界量必须一致）。
闸门
缺信号 = null，不补形状 某槽没有任一生理信号 → 该槽没有值，图上断开（间隔 >1h 不连线）。不做 cosinor 拟合、不画虚线（早期版本用 14 天拟合曲线填补缺失，已废弃）。
输出
48 槽 0–100 + 每槽信号数 卡上峰值时刻 = 实测活性最高那一槽（不是拟合峰值）；波动幅度 = (max − min) / 均值。

6全天状态趋势（今日状态）

这是一个逐 30 分钟递推的状态量，不是对某个生理量的直接映射。

S(t) = clamp( S(t−1) + recovery − drain + homeostasis, 0, 100 )

项取值说明
recovery
恢复		 K_REC_HRV × (HRV比−1) = 6/单位HRV 高于期望才有增益
K_REC_REST × (1−HR抬升) = 3.5静息恢复；EDA 高时打 4 折
上限 REC_CAP = 6单窗口最多回 6 分
drain
消耗		 K_DR_HR × HR抬升 = 4心率相对静息抬升比例
K_DR_STEP × 步数比 = 2.5步数 / 期望 600 步每 30min
K_DR_EDA × EDA波峰数 = 0.8窗口内皮电波峰计数（0–8）
K_DR_STRESS × 应激代理 = 1.5EDA 满量程归一
上限 DRN_CAP = 4单窗口最多掉 4 分
equilibrium
稳态目标		 EQ_REST = 95放松 / 小睡时的回拉目标
EQ_ACTIVE = 70活动时段
EQ_STRESS = 72久坐焦虑时段
K_HOME = 0.05每 30min 拉向目标 5% 的差距
睡眠段
v18.155 新		 K_SLEEP_CHARGE = 0.22睡眠窗每 30min 拉向目标 22% 的差距
SLEEP_ENTRY_LEVEL = 45睡前水位（曲线起点）
seed
晨间种子 S0 computeSeed() = clamp( 0.4×HRV分 + 0.25×RHR分 + 0.35×睡眠分 − 70 + 60, 0, 100 )
HRV/RHR 各自对「同周期相位的历史中位」评分（相位差异被基线吸收，不做额外相位惩罚）。睡眠分用 dailyStatus 自己的 computeSleepScore（绝对口径）。
wakeNorm = 历史 S0 中位，recoveryDelta = S0 − wakeNorm（±5 分内算「持平」）。
睡眠段
向 seed 一阶渐进（v18.155 改动） 旧实现是 prev + 4 + (95−prev)×0.05，不动点解出 175 ⇒ 睡够 6.5h 必然封顶 100，且整段不读任何睡眠质量量（睡眠分 20 与 100 画出同一条线）。
改为 prev + (seed − prev) × 0.22：睡不好就停在真正能恢复到的水位。起点同时从 seed 改为睡前水位 45，seed 归位到起床时刻。
输出
CurvePoint[] + 四档 切点 LEVEL_TOP 76 / LEVEL_MID 51 / LEVEL_LOW 26 → 充沛 / 平稳 / 偏低 / 不足。
由 realFlags 区分「戒指真实采样点」与「回填补齐点」，首页折线只画真实点。

7问题清单

按「会不会让用户看到自相矛盾的数字」排序。P0 = 同屏矛盾或整体偏移，用户能直接看出来；P1 = 数值失真但不易直接察觉；P2 = 结构隐患。

P0脑力准备度会因口径切换整体下移约 14 分
computeMorningReadiness() 里睡眠侧是 rec×80 + 20，其中 rec 取自「睡眠恢复/100」。
绝对口径（基线 < 5 晚）下，正常睡眠的 rec 约 0.75 → 睡眠侧 80 分；
相对口径（≥ 5 晚）下，和平时一样的 rec 是 0.50 → 睡眠侧 60 分。
⇒ 戴满 5 晚之后，脑力准备度会凭空掉 14 分（20 × 0.7），而用户的睡眠并没有变差。
已定位：同文件的 loadScore 计算里做了中性点补偿（sleepRecoveryNeutral），但 morningReadiness 这一路漏了。修法：把 rec 先归一到「相对中性点」再进公式，或让 morningReadiness 也接收 neutral。
P0三套「应激」链路并存，同一时刻可以互相矛盾
现在有三份独立实现：
① stressAlgorithm —— 主源用固件 stress 等级（0–12 → 0–100），EDA 稳健 z 兜底（详情页在用）
② emotionalStress + stressFeatures —— 6 特征加权融合 → 百分位（首页 chip 在用）
③ cortisolProxy —— 6 路信号水平偏离 → 0–100（睡眠节律卡在用）
三者基线窗口虽已统一到 14 天加权中心，但特征层与权重完全不同：②有「皮电上升趋势/波动度」而③有「活动/睡眠债」；对运动更是哲学相反——②把运动槽排除，③把活动当负相扣减。
⇒ 运动后可能出现「心理压力中等、皮质醇活性却很低」这类组合。
建议：短期至少在 UI 上明确三者不是同一个量（现在三张卡都写着「相对你自己」）；中期收敛为共享特征层 + 各自映射。
P0曲线 seed 的睡眠分与首页「睡眠恢复」不同源，且少一个维度
首页 chip 走 computeSleepPersonalized（相对口径，四维，含效率项）。
曲线 seed 走 dailyStatus.computeSeed 内的 computeSleepScore（绝对口径，SLEEP_REF=72）。
更细的一处：RingBleManager 构造 seed 输入时传的是 { sleepTotal, sleepDeep, getUp }，漏了 sleepAwake ⇒ 效率项（权重 0.22）被整项剔除后权重重归一。
⇒ 首页 chip 算 4 个维度，曲线 seed 只算 3 个；两者不会同步变化。
修法：seed 的睡眠项改为复用 computeSleepPersonalized().score，并补传 sleepAwake。注意 seed 是绝对量，接入相对分需要重新标定 W_S0_S 的语义。
P1夜间睡眠目标（seed）与白天静息目标（95）倒挂 —— v18.155 改动的副作用
这次把睡眠段目标从固定 95 改成 seed（通常 50–80）之后：
· 睡眠段：45 → seed，一觉最多收敛到 seed；
· 白天静息：只要久坐放松（HR < 静息×0.95、步数 <5、EDA 低），就按 K_HOME=0.05 被拉向 95。
⇒ 白天在沙发上坐一小时的状态值，可能高于整夜睡眠后的值，生理语义上讲不通。
建议：把「静息恢复目标」也个人化 —— 最自然的是 equilibrium_rest = seed（白天静息只能回到今晨的水平，不超越）。这样曲线自洽且单调合理：夜间充到 seed，白天消耗后小幅回升到 seed 附近。
P1皮质醇活性的「睡眠债」这一路从未接通
cortisolProxy 的权重表里 sleepDebt: 0.08，但取值依赖调用方传入 opts.sleepDeficit。全项目搜索，没有任何调用方传过它（AllDayRecoveryCard 调 buildCortisolProxyToday(bl) 时只传了基线）。
⇒ 权重 0.08 永远不参与，实际只有 5 路信号在工作，且注释里「六路信号」的说法与实现不符。
修法：要么在调用处算好 sleepDeficit 传进去，要么把这一路从权重表移除并修正注释（不能两者都不做）。
P1消耗项里 EDA 可以单项打满上限
drain = K_DR_HR·HR抬升 + K_DR_STEP·步数比 + K_DR_EDA·EDA波峰 + K_DR_STRESS·应激代理，最后 min(drain, DRN_CAP=4)。
而 EDA 波峰数上限 8、K_DR_EDA = 0.8 ⇒ EDA 单项最高 6.4，已超过 4 的封顶。
⇒ 只要窗口内有 5 个以上皮电波峰，drain 恒为 4，心率/步数/HRV 的贡献被完全吞掉，看不出是谁在消耗。
修法：各项先按自身量程归一再加权（现在是直接相加再截断），或提高 DRN_CAP 并调低各系数。
P1历史曲线重建时 HRV 全天恒定
rebuildDayTimelineFromHealthStore 里 const hrv = hrvDaily … —— 每个窗口用同一个日均值。于是 isRecoveringNow 的 HRV 条件（hrvRatio > 0.9）在整天恒定，
⇒ 「是否处于恢复态」实际只由心率/步数/EDA 决定，HRV 这一维在历史曲线上形同虚设。（实时路径读的是窗口内真实 HRV，两条路径口径不一致。）
P1基线成熟门槛不统一：5 晚 / 3 天 / 3 天
睡眠恢复要 ≥5 晚才进相对口径；心理压力与皮质醇活性都是 ≥3 天。同一个新用户，第 3–4 天会在首页看到「压力有数、睡眠还没数」。
不算错，但口径不一致会让人觉得成熟度是随机的。
P2「50 = 和平时一样」却标成「中等压力」
档位切点是 50 / 70，恰好把「和你平时完全一样」这个锚点划进「中等压力」档。
用户看到「55 · 中等压力」会理解成「我今天压力中等」，实际含义是「我今天和平时一样」。这和睡眠恢复那个 61 被读成「刚及格」是同一类语义冲突。
可选：档位名改成「低 / 与平时持平 / 高」三档（保持 50/70 切点），或把切点整体上移（如 55/75）让 50 落在低档。
P2「心理压力是否显示数字」有两份闸门判断
emotionalStress 内部导出 stressScoreVisible（= 校准通过 && 有值），但 UI 没有用它 —— TodayScreen 自己又写了一遍 calibration.level === 'invalid' 的判断。两处逻辑目前一致，改一处漏一处就会分裂。
P2「睡眠恢复」档位词目前有 5 套写法
首页 chip、睡眠节律卡 badge、SleepCard 三处本轮已统一到 sleepRecoveryTag()。
仍有两处独立：EnergyDetailScreen 用 0.75/0.55/0.35（措辞「恢复良好/一般/不足/严重不足」）、RingBleManager 头条用 seed 的 recoveryLabel（「优于平时/持平/差于平时」，走的是另一个量：S0 与历史 S0 中位之差）。
P2曲线起点 SLEEP_ENTRY_LEVEL = 45 是全局常量
睡前水位对所有人都是 45，而 seed 是个人化的。对「平时睡前就在 60」的人，曲线会在睡眠段向上爬；对「睡前 35」的人，曲线要先被抬到 45 —— 两种情况下睡眠段的形状都被这个常量塑形，而不是被真实恢复过程塑形。
P2冷启动文献基线是占位值
dailyStatus.LIT 那张按周期相位分桶的 HRV/RHR/睡眠群体基线，源码注释自陈「这些是占位文献常数值，正式上线前应替换为已发表的纵向研究数据」。冷启动用户的相位基线目前走的是这张表。
