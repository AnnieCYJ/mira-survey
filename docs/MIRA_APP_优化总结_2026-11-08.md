## 一、逻辑架构梳理（数据怎么走、AI 怎么接）

### 1.1 数据流：戒指 → 存储 → AI 综合分析

```
 戒指 / 固件回传 (RingBleManager)
        │  实时 handler + 离线回填 + 后端回调
        ▼
 ┌─────────────────────────────────────────────┐
 │  healthStore.daily[YYYY-MM-DD]   ← 按天隔离 │  ← 主存储（日聚合 + 逐时曲线）
 │  healthStore.intraday[YYYY-MM-DD]             │
 │  cycleLog (生理周期) / quickCheckStore·examStore (体检)  ← 独立 store，自然豁免跨天清零 │
 └─────────────────────────────────────────────┘
        │
        ▼  buildHealthSnapshot()  （src/ai/health.ts）
        │  今日实时 / 皮质醇节律 / 激素推断 / 情绪脑力 / 周期相位 / 近 7 天趋势
        ▼
 ┌─────────────────────────────────────────────┐
 │  src/ai/insight.ts  →  getAiInsight(kind)     │  ← 真实端侧大模型（Qwen2.5-1.5B）
 │  端侧 runOnModel + 云端 /v1/ring/ask 兜底      │     只读不写，按天缓存 30min，失败回落规则文案
 └─────────────────────────────────────────────┘
        │
        ▼  useAiInsight(kind) hook
   洞察页顶部「综合分析」/ 周期 tab / 身体恢复详情 / 首页今日状态分析 / 语音气泡建议
```

**铁律（已固化到 `src/data/metricRetention.ts`）：**
- **跨天清零**：压力、身心压力、血压，以及其余所有「每日指标」→ 新的一天从空对象重新累积。
- **豁免（留最新值）**：生理周期（`cycleLog`）+ 体检（`quickCheckStore` / `examStore`，含其 7 天 `getLatest` 窗口）。
- 实时缓冲 `RingBleManager.state.daily` 已加**跨天重置**（模块级 `_dailyResetDayKey` + `dailyBaseForNow()`）：所有写 `state.daily` 的路径（6 个实时 handler、离线回填、后端回调、`flushPending`、`syncExtendedDaily`、`loadPersisted`）全部过此函数，避免昨日残值（temp/spo2/血压/压力）挂到新的一天。

### 1.2 AI 接入双通道（都是真接，不是空壳）
- **端侧**：`src/ai/model.ts` 跑 Qwen2.5-1.5B（`runOnModel`），带设备令牌、上下文预算、缓存。
- **云端**：`src/ai/cloudAsk.ts` 走 `/v1/ring/ask`，带鉴权与兜底。
- 无任何 TODO / FIXME / 假数据占位。

## 三、本轮补上的优化（UI + AI，均 tsc 0 新增）

### 3.1 AI 优化
- **首页分析接真实 AI**（`src/components/CalmWaveHome.tsx`）
  - 新增 `import { useAiInsight }`；组件内 `const { text: aiAnalysis } = useAiInsight('overview')`。
  - 渲染逻辑：AI 文案可用 → 显示（限 3 行，避免挤占下方胶囊与指标卡）；不可用（模型未打包 / 无数据 / 推理中）→ 回落原有本地模板。
  - 与洞察页顶部**同源同缓存**，端侧 1.1GB 模型加载有 900ms 延后启动，首屏不卡。
  - 直接回应你之前的需求「首页分析要上 AI」。

### 3.2 UI 优化（延续审计清单）
- **无障碍热区 < 44pt**（视觉不变、点击区扩大）
  - `src/screens/CycleCalendarScreen.tsx`：孕期开关（原 48×28）加 `hitSlop`。
  - `src/screens/TodayScreen.tsx`：圆环箭头（原 width 30）加 `hitSlop`。
- **体检报告详情页体验**（`src/screens/QuickCheckDetailScreen.tsx`）
  - 修掉异步加载时**误闪「未找到该记录」**——新增 `loading` 态（「报告加载中…」+ spinner）。
  - 删除按钮新增 `deleting` 态（spinner 反馈），并在 `deleting` 期间禁用重复点击。
- **CTA 禁用态**（`src/components/quickCheckShared.tsx`）
  - 共享 `QCta` 按钮原本收了 `disabled` 却无视觉变化，新增 `ctaDisabled`（透明度 0.45）+ 锁定 `activeOpacity`，禁用态清晰可见。

### 3.3 之前已完成、本轮一并核对保留
- 跨天清零（`metricRetention.ts` + `RingBleManager` 实时缓冲重置）。
- `healthStore.getTodayValue(key, now)` 严格今日只读。
- ui.status 4 档状态色统一、三节律卡 icon、token 收敛（在用户 BLE WIP 工作树内，未提交）。

## 七、全仓收口执行结果（2026-11-08 续）

用户指令：「全仓收口先做」。本节记录实际执行与结论。

### 7.1 rgba → token（安全机械化部分，已完成）

- **目标 token 已存在**：`theme.colors.ui.white04~white97`（42 档）、`black06~black50`（14 档）是 2026-11-08 专门为「收口全仓 rgba」建的，1:1 精确映射。
- **执行**：脚本遍历 `src/`（跳过 `src/theme/*` 三个 token 定义文件本身），对 `rgba(255,255,255,A)` / `rgba(0,0,0,A)` 按 alpha 精确替换为 `theme.colors.ui.whiteXX` / `blackXX`。
- **结果**：**157 处跨 62 个文件**收口完毕；3 个原本没 import `theme` 的组件（`LunaMiraFace` / `MiraBot` / `ArcGauge`）自动补了 `import { theme } from '../theme/theme'`。
- **安全网**：tsc 跑完从临时 49（3 个 import 误带 `.ts` 后缀）修回到 **46 基线，零新增**。值相等 → 视觉零差异。

### 7.2 品牌色淡色 / 深海 scrim（93 处，留人工按语义定）

这些不是白/黑 alpha，全局硬替会**语义错配**，故未自动收：

| 裸值（采样） | 出现 | 建议语义 token（需设计确认） |
|---|---|---|
| `rgba(157,138,240,0.22)` 紫 | 4 | `colors.tileCog` / `cardGlowBrain` / `cycleLuteal` |
| `rgba(242,163,198,0.20)` 粉 | 3 | `colors.tileEmo` / `cardGlowEmotion` / `dangerSoft` |
| `rgba(126,166,248,0.22)` 蓝 | 3 | `colors.tileAct` / `cardGlowSport` |
| `rgba(121,103,210,0.20)` 靛 | 3 | 无精确 token，建议新增 `accentIndigoSoft` |
| `rgba(9,28,48,0.52)` / `rgba(4,18,38,0.72)` | 若干 | `sheetDeep` / `deepScrim` 体系 |
| `rgba(74,70,96,0.55)` 等中性灰 | 若干 | `onGlass*` 体系 |

> 动作建议：这些在「卡片/chip/相位」语境里各有专属 token，应由设计逐处确认用哪个，避免统一成 `whiteXX` 后丢失语义。属低优先、需眼检，本批未动。

### 7.3 间距扫（审计结论：已基本完成，无需脚本化硬替）

- `space.*` 引用 **974 处**，`theme.sp()` 是绝对主流；裸数字 padding/margin 全仓仅 **1 处** → 早期 token 收敛轮次已收口。
- 残余 126 处子 12pt 间距（`sp(0.5/1/1.5/2.5)` 等）经抽样**基本是合法微间距**：`gap` 小元素间隙、`left` 定位偏移、日历格 `padding: sp(0.5)`，**不是**文档定的「卡片内边距只两级（20/12）」破窗。
- 若盲改这些为 12pt 会破坏布局，且需真机眼检 → **标记人工按屏验收**，不脚本硬替。这与原计划「人工分批、不脚本化硬替」一致。
