# 今日状态（Daily Status）算法工程 Spec · v1

> 定位：**恢复就绪度（Recovery Readiness）**，不是净能量/运动分。
> 范围：0–100 分。结构 = **晨间恢复锚点 + 日间修正（±15 上限）**。
> 核心输入：相对"个人同相位基线"的偏离度，而非绝对数值。

---

## 0. 设计原则（已确认）

1. **恢复就绪度单轴**：今日状态只回答"你今天恢复得怎么样"，运动负荷独立成轴展示，**不扣今日状态分**。
2. **晨间锚点 ± 日间修正**：废弃"晨间分占 50% 权重"的说法（原汇总公式里从未体现）。晨间分是绝对锚点（0–100），日间只在其上做 ±15 封顶调整。
3. **相位专属基线（Phase-Specific Baseline）**：废止"全局基线 + 周期扣分"。所有带周期波动的指标（HRV / RHR / sleep）都相对"用户自己**同相位**历史中位"评分，相位差异被基线完全吸收，**无显式 phase_adjustment 项**。
4. **不造假**：只使用戒指真测或可严谨推导的量；量纲不明的 SDK 字段（如 `sleep_score`）不直接入算。

---

## 1. 整体公式

```
最终今日状态分 = 晨间恢复锚点分
               + 日间修正（stress_drain + hrv_drain − recovery_bonus）
               其中 日间修正 整体封顶 ±15

晨间恢复锚点分 = hrv_score × 0.40 + rhr_score × 0.25 + sleep_score × 0.35
```

---

## 2. 基线系统（核心）

### 2.1 存储与分桶
- 每日聚合按 **相位标签** 分桶存储：`卵泡期 / 排卵期 / 黄体早期 / 黄体晚期 / 经期`。
- 同时保留一份**全局个人**序列（不分桶），用于冷启动回退。
- 保留窗口：原始日数据 90 天；相位分桶中位按最近 90 天（≥2 个完整周期）计算。

### 2.2 基线计算（稳健统计）
对每个指标（hrv / rhr / sleep_score / eda_resting）在每个相位桶内：
- 用 **中位数 + MAD** 过滤异常（剔除 `|x − median| > 3×MAD`），再取中位。
- ❌ 不采用 `mean ± 2σ`（HRV 偏态，均值/标准差本身被异常拉偏）。
- **Phase 3 精炼（方差门控）**：当某指标「相位间差异 < 相位内噪声」时，退化为全局基线——避免对周期信号弱的指标（如部分 sleep 子项）做相位分桶反而放大估计方差。MVP 阶段统一全指标相位基线（逻辑一致、工程统一），上线跑真实数据后再按方差门控逐指标回退。

```
baseline[metric][phase] = median(filtered values in that phase bucket)
```

### 2.3 冷启动与回退（关键闸门）
优先级（取第一个满足的）：
1. 同相位样本数 ≥ `MIN_PHASE_SAMPLES (=8)` 且用户天数 ≥ 45 → **同相位个人基线**。
2. 全局个人样本 ≥ 8 → **全局个人中位基线**（不显示"vs 同期"文案）。
3. 否则 → **文献默认女性群体基线**（按相位分桶的常量表，见 §6 TBD-1）。

> 发烧日（`fever` 标记）**永不计入**任何基线窗口（spec 与实现必须一致，原伪代码漏了）。

## 3. 晨间恢复锚点分

所有 ratio 均相对**同相位基线**；无相位可用时回退全局基线（§2.3）。

```python
# hrv_score：中性锚点 70，ratio=1.0 → 70；ratio=1.5 → 95；ratio=0.6 → 50
hrv_ratio   = today.hrv / baseline.hrv[phase]
hrv_score   = clamp(ANCHOR + (hrv_ratio - 1.0) * K_HRV, 0, 100)   # ANCHOR=70, K_HRV=50

# rhr_score：越低越好，基线最优区为 ratio≈0.85（静息比基线低 15%）
rhr_ratio   = today.rhr / baseline.rhr[phase]
rhr_score   = clamp(ANCHOR - (rhr_ratio - 0.85) * K_RHR, 0, 100)  # K_RHR=100

# sleep_score：自算，0–100，见 §4
sleep_score = self_computed_sleep_score(today)

morning_score = hrv_score*0.40 + rhr_score*0.25 + sleep_score*0.35
```

**无显式 phase_adjustment 项**——相位差异已由基线吸收。

## 4. 睡眠分自算（规避 SDK 量纲风险）

SDK 透传的 `summary.score` 量纲未知（日志见过 `=2`），**禁止直接入算 35% 权重**。改为从可用字段归一化：

```
duration_norm = clamp(today.sleepTotal / TARGET_DURATION, 0, 1)      # TARGET_DURATION=7.5h
deep_norm     = clamp(today.sleepDeep% / TARGET_DEEP, 0, 1)          # TARGET_DEEP=20%
eff_norm      = clamp(today.sleepEfficiency / TARGET_EFF, 0, 1)      # TARGET_EFF=90%
getup_norm    = clamp(1 - today.getUpTimes / TARGET_GETUP, 0, 1)     # TARGET_GETUP=1

sleep_score = 100 * (W_D*duration_norm + W_DEEP*deep_norm + W_EFF*eff_norm + W_G*getup_norm)
# 建议权重 W_D=0.3, W_DEEP=0.3, W_EFF=0.25, W_G=0.15（TBD 标定）
```
> TBD-2：确认 `sleepEfficiency` / `sleepDeep%` 在 Mira SDK 的字段名与量纲，必要时用 `sleepTotal/deep/light/rem/getUp` 推导。

## 5. 日间修正（快照级，非实时）

受硬件限制（无连续 HRV、无加速度计），日间修正按 **healthGlance 快照频率（每 ~300s / 5min）** 更新，不要求真·实时。

```python
# 5.1 HRV 日内偏离（修正昼夜节律偏差）
intraday_hrv_expected = morning_hrv * 0.90        # 日内基准=晨间 90%（circadian floor）
hrv_drain = clamp((intraday_hrv_expected - current.hrv) / baseline.hrv_std[phase] * 2, 0, 5)
# 仅惩罚低于日内期望，正常午后衰减不再系统性扣分

# 5.2 EDA 应激消耗（静息基线取同相位夜间最低 10%）
eda_ratio   = current.eda / baseline.eda_resting[phase]
stress_drain = clamp((eda_ratio - 1.5) * 5, 0, 10) if eda_ratio > 1.5 else 0

# 5.3 运动负荷：仅展示，不扣分（独立 Strain 轴）

# 5.4 恢复补偿（封顶）
recovery_bonus = min(RECOVERY_CAP, rest_minutes / 10 * 0.5)   # RECOVERY_CAP=5

current_score = clamp(morning_score - (hrv_drain + stress_drain) + recovery_bonus,
                      morning_score - 15, morning_score + 15)  # 整体 ±15 封顶
```

## 6. 相位识别

- **主键**：`cycleMath`（上次经期开始日 + 周期长度）推导。
- **辅助（仅提示，不当主键）**：体温双相变化。⚠️ 皮肤温噪声大，**不可靠地自动划相位边界**。
- **未记录经期 / 周期不规律**：回退"假设 28 天"或标"未记录"，使用全局基线，界面**不显示"vs 同期"**对比文案。
- **数据成熟度**：见 §2.3 闸门，避免错标日期污染分桶。

## 7. 输入映射与可得性（工程落地的真正工作量）

| 算法变量 | 戒指 SDK 来源 | 可得性 | 备注 |
|---|---|---|---|
| HRV（晨/快照） | `healthGlance.hrv` | ⚠️ 快照级，无连续；HK18 历史库 `totalDay=0` | 日间修正频率受限 |
| 静息心率 RHR | 睡眠期 min HR（需新增采集） | ❌ 暂无 | **缺口**：需记录夜间最低 HR |
| 静息 EDA | `skinMoisture`/`cortisol`/`sns` 或 GSR | ⚠️ 快照 | 需定义"静息=夜间最低 10%" |
| 睡眠字段 | `sleepTotal/deep/light/rem/getUp/efficiency` | ✅ | 来自 `VPDataBaseOperation` |
| 运动/活跃度 | `Step`（步数）+ `hr` 抬升 | ⚠️ 近似 | 无加速度负荷，用步数+HR 近似 Strain |
| 体温 | `healthGlance` 皮肤温 | ⚠️ 噪声大 | 双相图另算，不进今日状态分 |
| 相位 | `cycleMath` + 体温双相(辅助) | ✅/⚠️ | 见 §6 |

> **最大落地风险不在算法，在输入映射表 + 两个采集缺口（夜间 min HR、静息 EDA 定义）。**

## 8. 分数 → 精力等级（4 级）

> **关键定位：等级是纯展示层，与算法完全解耦。**算法只输出一个 0–100 的 `daily_status_score`，UI 层用一个 `mapScoreToLevel(score)` 纯函数把它转成 4 个字。该映射**不依赖任何算法细节**，算法未定稿时即可先行实现（切点先写死），后续仅调切点常量即可，不影响算法模块。

| 展示分（百分位） | 等级 | 文案 |
|---|---|---|
| ≥65 | 精力充沛 | "状态良好，可安排重要工作" |
| 30–64 | 精力平稳 | "处于正常波动，按节奏推进" |
| 5–29 | 精力偏低 | "需要主动休息，建议轻活动" |
| 0–4 | 精力不足 | "今日恢复差，优先休息" |

> **展示分 = 百分位（归一化层）**：内部算法输出一个单调的 `raw_readiness`（晨间锚点 ± 日间修正）。展示前经**归一化层**映射为 0–100 的 `daily_status_score`：
> `daily_status_score = 100 × P(raw_readiness ≤ 今日值)`，其中 P 由用户自身滚动历史（≥30d）的经验 CDF 估计；冷启动（<30d）用群体参考分布（来自 calibration 数据，见 §12）。
> 这一层同时解决两个用户痛点：① **分数均匀好懂**——"你的分 = 你比过去百分之几的日子好"，不再出现"天天 70 分看不懂"；② **图表均匀好看**，且档位切点稳定。
> 档位切点设在百分位 **65 / 30 / 5**，对应 **充沛=top35% / 平稳=30–65% / 偏低=5–30% / 不足=bottom5%**——即 **『不足』约占 5%（稀有且严肃）**，匹配产品意图；其余三档覆盖 95% 的正常波动。
> 归一化使"档位分布"与"原始公式是否压缩"解耦：即使内部分被结构压缩，展示层仍健康（见 §12 回放验证——原崩坏公式归一化后档位即 5/25/35/35）。但仍建议按 §12 修原始灵敏度，因归一化不改相对排序，原始越准、百分位叙事越真。
> 切点/百分位边界为初始默认，跑真实逐日数据后按 TBD-4 复核（仅需调边界常量，结构不动）。

### 首页展示建议（相位为核心叙事，分数为百分位）
```
今日状态：78 分
黄体晚期 · 精力充沛
"你目前处于黄体晚期（周期第 24 天），今日恢复水平优于以往同期约 78% 的日子。"
```
文案明确"与过去同期的自己比"（百分位语义），避免跨相位焦虑。

## 9. 边缘案例

| 场景 | 处理 |
|---|---|
| 发烧（皮肤温 > 阈值 TBD，等效 >37.5℃） | 当日 −15，且 `fever` 标记，**不计入**任何基线窗口 |
| 新用户（<45 天） | 文献默认群体基线，不显示"vs 同期" |
| 同相位样本 < 8 | 回退全局个人基线 |
| 周期不规律 / 未记录经期 | 全局基线 + "未记录"相位，无对比文案 |
| 经期第 1–2 天 | 自然偏低由基线吸收，**不再额外扣**（与全局一致，无双重惩罚） |

## 11. MVP 落地排期

- **Phase 1（核心可上线，最大工程量在基线系统）**：**相位专属基线系统（分桶存储 + MAD 过滤 + 冷启动三段回退）** + 晨间锚点分（HRV ratio + RHR ratio + 自算 sleep）× 相位基线 + 4 级映射。注意：基线系统是 Phase 1 的真正工作量所在，日间修正反而是最轻的部分。

- **Phase 3（完善）**：文献分相位群体基线（TBD-1 构造法）、体温双相辅助、不规则周期处理、方差门控（§2.2）、真实数据校准（TBD-4）。

## 12. 校准实证（collector.log 真实回放 v0）

> 为给 TBD-4 提供证据基，已用真实戒指日志回放原型（脚本 `tools/calibrate_dist.py`）。**结论：默认常数严重失真，必须校准；"向下更敏感"的产品立场被真实数据证实。**

**数据来源**：`/tmp/mira-logs/collector.log`（真实戒指，单会话、仅 HH:MM:SS 无跨日边界；以"快照分布"近似，HRV 中位作 14d 基线代理）。

**真实输入分布（抽样）**：
- **HRV**：中位 **40ms**，范围 20–253；其中 **>120ms 占 ~24% 判为传感器伪迹**（本中位下 250ms 不符合生理），过滤后 87 样本、中位 40ms、主体聚于 26–39 + 长尾。
- **HR**：中位 73bpm，范围 53–112（近似正态）。
- **体温**：中位 36.6°C，范围 35.6–37.2。
- **睡眠**：`total=552 / deep=165(30%) / light=266 / rem=116(21%) / SDKscore=2` —— **SDK score=2 印证 0–5 量纲（非 0–100），§4 自算决策正确**。

**当前公式（spec 默认 ANCHOR=70, K_HRV=50, 权重 0.4/0.25/0.35）**：
- 分数动态范围仅 **65–86**（结构压缩：60% 分项用常量 + HRV 仅 40% 权重、K 偏小）。
- 档位占比（切点 70/50/35）：**充沛 97% / 平稳 3% / 偏低 0% / 不足 0%**。
- 上调顶部至 78/58/42：充沛 31% / 平稳 69% / 偏低 0% / 不足 0%（顶部改善，底部仍全盲）。

**更敏感变体（演示方向，非最终）：HRV 权重 0.5 / K_HRV=120 / 低于基线 ×1.6 不对称**：
- 范围拉开到 **38–88**，档位：充沛 63% / 平稳 32% / 偏低 4% / 不足 1%——**低档首次出现样本，证明校准方向成立**。

**TBD-4 据此修订为（不再纯猜测）**：
1. **HRV 伪迹过滤前置**：基线计算与评分前剔除 `hrv>120ms`（及 `<15ms`）的快照，避免伪迹污染基线 + 虚高分数。
2. **提高下行灵敏度**：HRV 权重 ↑ 至 ~0.5；`K_HRV` 由 50 → ~120；并对 `ratio<1`（低于基线）做不对称放大（×1.6），使中度下行能掉进『偏低』。
3. **顶部阈值大幅上调**：默认 70 导致 97% 充沛，真实数据下顶部档应 ≥78（具体验证后定）。
4. **保留 <35 仅为真警报**：与"向下更敏感"不矛盾——敏感度提升的是『偏低』档（中度下行），『不足』仍只留给明显低于基线/真出事。
5. **展示层归一化（见 §8）**：`raw_readiness` 经经验 CDF 映射为均匀 0–100 展示分，档位切点设在百分位 **65/30/5 → 不足≈5%（稀有严肃）、偏低25%、平稳35%、充沛35%**。此层使档位分布与原始公式压缩解耦：回放已验证，即便原崩坏公式（97% 顶档）经归一化后档位即 5/25/35/35，图表均匀、底部稀有。原始灵敏度（点 1–3）仍建议修，因归一化不改相对排序。

> **重要局限**：本回放为单人、单会话、会话内中位基线，非真·逐日 14d 基线；真实上线后逐日数据或使范围再收窄，但**"分数结构压缩 + 需向下更敏感 + 顶部阈值需大幅上调"三个结论方向已锁**，Phase 1 实现时即按此方向设初值，待逐日数据回填后做最终定标。

## 13. 实现状态（Phase 1 已落地，2026-09-01）

算法第一版已按本 spec 实现并通过 node 单测（11/11）：

- **算法核心（纯 TS、零 RN 依赖）**：`src/lib/dailyStatus.ts`
  - `BaselineStore`：按相位分桶存储 + 中位数+MAD 过滤 + 冷启动三段回退（同相位个人→全局个人→文献群体常量表 `LIT`）。
  - `computeSleepScore`：自算（时长/深睡%/起夜），规避 SDK `sleep_score` 量纲未知。
  - `computeDailyStatus`：晨间锚点（HRV ratio 中性 70、K_HRV=120、下行不对称×1.6；RHR ratio 最优 0.85；sleep 自算）→ 加权可用项 → 经验 CDF 归一化为均匀 0–100 展示分 → 4 级映射（切点 65/30/5）。
