图表 / 卡片尺寸统一规范

针对「情绪页面的图和睡眠页面的图大小不一致」的专项审计，以及一套可直接落地的统一尺寸规则。

审计范围：src/components · src/screens 全部 SVG 图表与卡片容器 · 2026-10-09

结论：确实没有统一。全站共有 16 种不同的图表高度（64 / 72 / 80 / 96 / 120 / 150 / 170 / 180 / 198 / 200 / 210 / 240 / 280 / 330 / 360 / 380）， 而且同一个组件内部也存在两套高度。你看到的三处差异，全部能被这张表复现。

一、你发现的三处差异 · 逐条定位

你观察到的现象对应文件实际数值说明
睡眠页面的图「好大」 SleepDualAxisChart.tsx H = 380 全站最高的一张图。它把「轴标题带 44 + X 轴标签带 40」共 84pt 的装饰高度算进总高，比同类详情页图多出约 140pt。
情绪页面「这个图有点小」 EmotionInsightView.tsx chartH = 170 情绪洞察卡用的是 170，比详情页同主题的图矮一大截。
情绪页面「那个图挺大的」 EnergyDetailScreen.tsx 280 / ≈330 同一页里两张图：主趋势 280；另一张 chartH=194 却被渲染成 height={chartH * 1.7} ≈ 330——被强行拉伸 1.7 倍。

三、根因（4 条）

  • 没有共享的图表高度 token。20+ 处各自写死 const H = … / const CHART_H = …，谁都不引用谁。
  • 同一组件内部两套高度。CortisolRhythmCard 同时有 72 和 120；InsightScreen 同时有 64 和 80；EmotionRangeBars 同时有 198 和 180。
  • SVG 渲染高度 ≠ viewBox 高度，造成非等比拉伸。EnergyDetailScreen 用 viewBox={0 0 VW 194} 配 height={chartH * 1.7}，实际渲染 330——同页两图比例彻底失真。
  • 装饰高度没有被单列。睡眠双轴图把轴标题带(44)+X轴标签带(40)塞进总高，导致「总高 380」看起来是别的图的 2 倍。

四、统一规则（核心产出）

规则 1 · 图表高度只分 4 档

原则：图表高度只由「信息层级」决定，不由「它在哪个页面」决定。 同一层级的图，无论在首页、洞察页还是详情页，必须等高。

规则 2 · 装饰高度从总高里剥离

轴标题带、X 轴标签带、图例带属于图表外框，不再是「想加多少加多少」。每档固定预算： XS/S 卡内图 ≤ 24pt，M/L 详情图 ≤ 50pt。 睡眠双轴图当前 84pt 的装饰高度严重超标 → 必须收紧（PAD_T 44→32、PAD_B 40→28），而不是靠把总高堆到 380 来解决。

规则 3 · 禁止非等比拉伸

SVG 的 height 必须等于 viewBox 的高度（1:1）。 禁止 height={chartH * 1.7} 这类写法。想要更高，就改档位（换 token），不要乘系数。

规则 4 · 卡片内边距只允许 2 级、圆角只允许 3 级

六、落地建议 · 分三步

Step 1 · 建 token

在 src/theme/chart.ts 增加高度档位与装饰预算： h:{xs:64,s:96,m:180,l:240}、chrome:{card:24,detail:50}。

Step 2 · 修 3 个重灾区

① 睡眠双轴 380→240（收紧装饰带）② 情绪详情 ×1.7 拉伸去掉 ③ CortisolRhythmCard / InsightScreen 内部两套合并。

Step 3 · 全量换 token

把剩余 15 处硬编码 H 换成对应档位 token，跑 tsc（基线 42）确认零新增。

验收

情绪页与睡眠页同层级图并排截图应等高；App 内不再出现 * 1.7 类拉伸系数。

本文件为规范文档，尚未改动 App 源码。确认后按 Step 1→3 落地。
